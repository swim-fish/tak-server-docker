# 2026-09-23 MediaMTX 本機驗證

## 環境與設定

- Windows Docker Desktop，Compose 專案 `tak-local`，MediaMTX `bluenviron/mediamtx:1.21.1`。
- 熱點主機 `192.168.137.1`、mDNS `takbox.local`，Android 裝置連到同一熱點。
- TAK Root → 中繼 CA 簽發 MediaMTX 獨立 `serverAuth` 葉憑證；SAN 使用 `DNS:takbox.local`。金鑰、帳密及實際 YAML 留在忽略版控的 `runtime/`。
- `rtspEncryption: optional`，獨立發布／讀取帳號；允許 `test` 與 `live/` 前綴路徑。

## 已通過

1. `docker compose config --quiet` 通過，容器載入設定並啟動 RTSP `8554/TCP`、RTSPS `8322/TCP` 及 `8000-8001/UDP`、`8004-8005/UDP`。
2. OpenSSL 驗證葉憑證的簽發鏈、`serverAuth` 及 `takbox.local` 主機名稱通過。Windows Python TLS client 連主機對外 `8322`，驗證 Root CA 及 SAN，協商 TLS 1.3。
3. 固定 FFmpeg 測試映像在 Compose 網路，對 RTSP 與 RTSPS 各以 TCP、UDP 發布及讀取 H.264 測試影像，四組皆通過。
4. 獨立 Docker bridge 經 Windows 發布位址 `192.168.137.1`，RTSP 與 RTSPS 的 TCP 發布、讀取通過。
5. 無憑證的 RTSP `DESCRIBE` 回應 `401 Unauthorized`。
6. Android 經熱點解析 `takbox.local → 192.168.137.1`，可連通 TCP `8554`、`8322`。這只證明連線入口可達，不代表 ICU 已成功發布。
7. 使用者在 Android TAK ICU 7.5.1 啟用 `Use SSL?`、填入 `takbox.local:8322` 與發布帳密後回報串流啟動。MediaMTX 同時記錄 `[RTSPS] is publishing to path 'live/VIDEO_1'`，來源為熱點端經 Docker Desktop 轉入的連線。
8. 使用獨立 `atak-viewer` 帳號、指定 TAK Root CA 與 TLS 驗證，從該 `live/VIDEO_1` RTSPS 串流成功讀取數秒影像。這確認伺服器端有可讀的影像，不只是一條空的 RTSP session。
9. `Install-MediaMtxFirewall.ps1` 已經由一般 PowerShell 請求 UAC，產生兩條限制 `192.168.137.1`、熱點介面與 `192.168.137.0/24` 的 TCP／UDP 規則；安裝後 Android TCP `8554`、`8322` 仍可達。
10. ICU 改回 RTSPS 後，MediaMTX 再次記錄 `live/VIDEO_1` 發布，獨立讀取端再次成功取得影像。相同影像也可由 Windows 已發布的 RTSP `8554/TCP` 入口，以 `atak-viewer` 帳號讀取；此讀取入口沒有 TLS，只限受信任網段。

## 待驗與失敗界線

- 獨立 Docker bridge 經 Windows 已發布入口進行 RTSP UDP **讀取失敗**：MediaMTX 顯示 UDP session，但 FFmpeg 未收到可解碼影像。這個路徑涉及 Docker Desktop NAT 與測試容器自身的 UDP 回程；不能據此宣稱 Android UDP 一定失敗。Android 端 RTSP／RTSPS UDP 尚未驗收。
- ICU 已完成 RTSPS＋帳密發布，但僅由成功連線無法推論它是否嚴格驗證 TAK CA 與 SAN；若要確認拒絕行為，需另外安排不受信任或 SAN 不相符的憑證測試。
- Android ICU 的純 RTSP 實測**未成功維持影像**：MediaMTX 兩次接受 `live/VIDEO_1` 發布 session，約 10 秒後均記錄 `session timed out`。路徑與帳密已通過伺服器檢查；結合 ICU 7.5.1 的 RTSPS 分支明確加上 TCP 選項、純 RTSP 分支沒有該選項，以及 Docker Desktop 對 UDP 映射的已知限制，推測純 RTSP 嘗試走 UDP，但尚未擷取封包來證實。此部署先以已通過的 RTSPS over TCP 使用。
- ATAK 內建播放器對 RTSPS 的相容性尚未實機確認。本次獨立讀取端使用 FFmpeg。
- FFmpeg 測試影像使用 `test` 路徑；ICU 實際發布到 `live/VIDEO_1`。
