# 20 分鐘 TAK 裝置憑證到期測試

本次使用獨立測試憑證觀察 ATAK 與 TAK Server 8089 在憑證到期前後的反應。測試包與私鑰只保存在 Git 忽略的 `runtime/` 和測試裝置 Download，不納入本紀錄。

| 項目 | 設定 |
| --- | --- |
| 裝置 | Alpha 測試裝置（使用者操作 ATAK） |
| 憑證 CN | `expiry-probe-20260926-164312` |
| 序號／CRL ID | `7A992BB2` |
| 群組 | `local-test` In + Out |
| `notBefore` | 2026-09-26 16:43:14（臺灣時間） |
| `notAfter` | 2026-09-26 17:03:00（臺灣時間） |

## 到期前基線

- 16:43:12 送出簽發要求，憑證與 DPK 建立成功；TAK 註冊讀回 `registered=true`。
- 16:46:15 使用該憑證對 8089 建立新的 TLS 連線，伺服器接受。
- 16:47:16 建立一條持續的 TLS 1.3 連線，定期傳送測試 CoT；伺服器有回傳資料。
- 16:48:35 起，每 30 秒使用同一張憑證建立新 TLS 連線並傳送測試 CoT，記錄交握與伺服器回應。原始狀態保存在 Git 忽略的 `runtime/validation/expiry-20m/`。
- 測試 DPK 以 ADB 放入裝置 Download，使用者手動匯入、停用原有 TAK 連線設定，並確認新憑證已連上 `takbox.local:8089:ssl`。

## 到期後觀察

> **關鍵結果：憑證到期不會讓已建立的 8089 TLS 連線立即失效。**本次到期前建立的連線，在到期後持續不中斷的測試期間仍可傳送 CoT、接收伺服器資料；只有斷線後嘗試建立的新連線遭到拒絕。不能單靠憑證到期時間，當作既有連線立即停止收發資料的機制。

| 臺灣時間 | 測試 | 結果 |
| --- | --- | --- |
| 17:02:36 | 使用該憑證建立新 TLS 連線並傳送 CoT | 成功，收到伺服器資料 |
| 17:03:07 | 到期後再次建立新 TLS 連線 | 遭拒；收到 TLS `certificate expired` 警示 |
| 17:03:24、17:03:54 | 到期前建立的同一條 TLS 連線繼續傳送 CoT | 連線仍存續，並收到伺服器資料 |
| 17:03:37、17:04:07 | 其他新連線重試 | 均收到 `certificate expired` 警示 |
| 17:04:54 | 原有 TLS 連線繼續傳送 CoT | 仍收到伺服器資料；17:05:24 由測試腳本依預定時間主動結束 |

使用者後續確認 ATAK 實機的現象：憑證到期時，原本已建立的連線沒有立刻斷線；下次重新連線才無法繼續使用。這是使用者的畫面觀察，尚無本次重連的 Android log 或截圖可記錄精確錯誤文字。

因此，這次 TAK Server 8089 在**新 TLS 連線**時檢查憑證有效期；已建立的 TLS 連線只要維持不中斷，在本次觀察期間即使憑證過期仍能繼續收發資料。這項觀察不保證連線能無限期存續。到期日不等於 CRL 撤銷；本次不撤銷中繼 CA，也不發布新的 CRL。
