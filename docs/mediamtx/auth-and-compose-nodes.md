# MediaMTX authorization and Compose node relationships

Reviewed on 2026-09-30 against repository revision `dae15e6`. This document describes the configuration generated by this repository, rather than a live-container inspection. The Compose stack pins all three MediaMTX services to `bluenviron/mediamtx:1.21.1`.

## Authorization with `authInternalUsers`

![MediaMTX authorization and permission boundaries](../images/mediamtx-auth-internal-users.png)

[Vector image](../images/mediamtx-auth-internal-users.svg) · [Editable Mermaid source](diagrams/mediamtx-auth-internal-users.mmd)

Each MediaMTX process loads its own `authInternalUsers` list. With `authMethod: internal`, the process checks the requested identity, action, source IP and path against that list. A path beginning with `~` is a regular expression; an exact path grants only that path. In the current generated entries, `ips: []` imposes no per-user source-IP restriction. Compose host bindings and host firewall rules form a separate network boundary. See the [upstream authentication reference](https://mediamtx.org/docs/features/authentication).

| Node | Identity | Action | Granted paths / purpose |
| --- | --- | --- | --- |
| `mediamtx` | `atak-publisher` | `publish` | `~^(live/.+|test)$`; retained legacy shared publisher |
| `mediamtx` | `icu-<squad>` | `publish` | Registered exact member paths; named squads additionally get `~^live/<squad>/(?:[A-Za-z0-9_-]+/)*VIDEO_1$` |
| `mediamtx` | `device-<generated-id>` | `publish` | The single exact path assigned to the device |
| `mediamtx` | `atak-viewer` | `read` | `~^(live/.+|test)$`; shared by ATAK, downstream nodes and thumbnail extraction |
| `mediamtx` | `tak-console` | `api` | Main-node API; no `publish` or `read` grant |
| `media-viewer` | `any` | `read` | `~^live/.+$`; includes anonymous readers behind the LAN gateway |
| `media-viewer` | `tak-console` | `api` | Public-viewer API for session inspection and termination |
| `media-preview` | `admin` | `read` | `~^live/.+$`; uses the share-admin password |

The named-squad regular expression covers valid nested paths ending in `VIDEO_1`; it is broader than the current registered list of members. The `default` squad receives only its registered exact paths. Disabled registry entries are omitted from the rendered dynamic users. The retained `atak-publisher` grant is still broad: scoped squad/device accounts do not remove this account's existing access.

`scripts/media_registry.py` creates or updates publisher identities in `runtime/mediamtx/publishers.json`, renders `mediamtx.yml` from the template, and verifies loaded permissions through the main-node API. If verification fails, it restores the previous configuration. The console's disable/reset operation also calls the session-kick helper after updating permissions; removing a user entry and terminating an established session are separate operations.

The upstream `atak-viewer` identity can read every allowed `live/` path. This deployment does not implement per-team read isolation in MediaMTX. TAK groups select which Video Alias records a client receives; the credentials carried by an alias govern actual stream access. Changing alias visibility alone does not revoke previously delivered read credentials.

RTSPS uses the MediaMTX server leaf certificate to protect transport. Stream authorization uses the configured username/password; the template does not configure TAK client-certificate authentication for media access. Examples below contain placeholders only:

```yaml
authMethod: internal
authInternalUsers:
  - user: device-example
    pass: <generated-device-password>
    ips: []
    permissions:
      - action: publish
        path: live/drone/example
  - user: atak-viewer
    pass: <shared-read-password>
    ips: []
    permissions:
      - action: read
        path: '~^(live/.+|test)$'
```

## Three MediaMTX nodes in Docker Compose

![Three MediaMTX processes and their gateways in Docker Compose](../images/mediamtx-compose-nodes.png)

[Vector image](../images/mediamtx-compose-nodes.svg) · [Editable Mermaid source](diagrams/mediamtx-compose-nodes.mmd)

The three nodes share the `tak-edge` network and use Compose service names for internal connections. They mount the same host configuration directory, but start with different files and maintain separate streams, sessions and authorization lists. The configured topology has one ingress node and two on-demand WebRTC reader nodes. It has no configured cluster membership, state replication, load balancer or failover. Compose service discovery supplies names such as `mediamtx` and `media-preview`; it does not replicate their media state. See [Docker Compose networking](https://docs.docker.com/compose/how-tos/networking/).

| Service | Configuration | Role | Host-published ports |
| --- | --- | --- | --- |
| `mediamtx` | `/config/mediamtx.yml` | RTSP/RTSPS publication, direct ATAK reading, main API | `TAK_BIND_IP`: TCP 8554/8322; UDP 8000/8001/8004/8005 |
| `media-viewer` | `/config/viewer-public.yml` | Public WebRTC reading; anonymous `live/` read grant | `TAK_BIND_IP`: TCP/UDP 8189; HTTP 8889 and API 9997 stay inside Compose |
| `media-preview` | `/config/viewer-preview.yml` | Independent authenticated operator WebRTC reading | Loopback: TCP 8890 → container 8889; TCP/UDP 8190 |
| `media-viewer-gateway` | `/media-config/viewer_state.json` | LAN HTTP/WHEP relay and persistent public-viewing switch | `TAK_BIND_IP`: TCP 8889 |
| `share-admin` | Registry/config directory and Compose secrets | Console, preview relay, configuration changes and API operations | Loopback: `${SHARE_ADMIN_HOST_PORT:-8766}` → container 8766 |

`TAK_BIND_IP` defaults to the repository's local-network binding. The documented workstation setup uses console port 10066 through an environment override; the literal Compose fallback is 8766. The two values should not be mistaken for different administration services.

Both downstream nodes use this generated source definition:

```yaml
paths:
  '~^(live/.+)$':
    source: rtsp://atak-viewer:<shared-read-password>@mediamtx:8554/$G1
    sourceOnDemand: true
    rtspTransport: tcp
    rtspDemuxMpegts: true
```

For a request to `live/alpha/1/VIDEO_1`, `$G1` resolves to that complete path. The downstream node initiates an authenticated RTSP/TCP read from the main node when a viewer needs it, then serves WebRTC to its own readers. Public and preview nodes can independently pull the same upstream path. The repository configures remuxing/demultiplexing and routing; these nodes do not add a configured video transcoder. The main template has RTMP, HLS, WebRTC, SRT and MoQ disabled; the downstream files enable WebRTC and disable RTSP serving.

The public browser sends HTTP/WHEP signaling through `media-viewer-gateway`, which checks `viewer_state.json` and rejects stopped viewing. It does not implement an individual viewer login; `media-viewer` grants anonymous `read` access to `live/` behind this gateway. WebRTC media uses the separately published ICE port 8189 and DTLS-SRTP. Setting public viewing off writes the state file and kicks existing `media-viewer` WebRTC sessions through its API. This operation is independent of the main stream node and `media-preview`.

The local console authenticates `admin` in `share-admin`, which relays preview HTTP/WHEP requests to `media-preview:8889` with the same admin credential. Preview media uses ICE 8190. The console also uses `tak-console` on `mediamtx:9997` and `media-viewer:9997`; neither API has a host port mapping. JPEG thumbnails use a separate short FFmpeg read from the main node with `atak-viewer`, rather than an additional MediaMTX node.

The main node's plain RTSP and both downstream source URLs use no TLS. Public and preview HTTP signaling also use no HTTPS in this local stack; WebRTC media is encrypted with DTLS-SRTP. `depends_on` establishes service startup ordering, while these definitions do not add a MediaMTX readiness health check. Runtime health and device playback require their own checks.

## Rebuild the figures

The [renderer](render_auth_node_diagrams.py) writes both PNG and SVG files from a shared layout. It needs Python and Pillow, and supports `--font-dir` for a directory containing `DejaVuSans.ttf` and `DejaVuSans-Bold.ttf`; on Windows it uses Segoe UI by default.

```powershell
python docs/mediamtx/render_auth_node_diagrams.py
```

The Mermaid files provide independently editable semantic diagrams. After changing the topology, update the Mermaid sources and renderer labels together, then inspect the resulting images.
